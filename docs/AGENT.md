| 编号 | 约束 |

| A01 | 新工程从无真实凭据的独立目录规范纳管；使用旧凭据或接入相关生产服务前完成对应轮换、外置和权限治理；旧版“不用 git”不构成长期禁令 |

| A03 | 不改旧业务代码、配置和库，不停止原任务；新工程独立存储。旧系统继续正常生产运行 |

| A06 | 不扫描或批量操作无关个人目录；保留修订前文档以便恢复 |

## 2. 工程与安全底线

| 编号 | 约束 |
|---|---|
| B01 | 任何交付均不暴露真实凭据；秘密只由受限运行配置或密钥服务注入 |
| B02 | 多人使用时服务端校验身份与账户范围；请求筛选和前端隐藏不能代替权限 |
| B03 | 凭据轮换按 Q7；历史明文数据副本及备份访问受控，不随源代码分发 |
| B04 | 审计追加记录，业务角色不可改；日志/审计/导出最小化、脱敏并按权限与期限存储 |
| B05 | 原暂停/否词及获准新增百度动作均需预览、人工确认、必要审批、执行、读回及结果留痕；撤回按动作定义，不承诺外部批量操作原子性 |
| B06 | 环境配置与凭据统一注入；账户规则、阈值、负责人映射等业务配置可入受控运行数据库，须登记、校验、版本和权限 |

人工改判不被自动覆盖，有转化及边界词不得被自动误否或误暂停。保护针对风险动作，不排除报表展示或有转化种子。此约束与是否选用增强无关。

## 3. 质量与运行

- 业务语义优先保留，旧接口名与代码结构可改；未核实能力不标为已有。
- SQL 值参数化、动态字段白名单，权限/过滤/稳定排序先于分页；映射及聚合粒度改变必须对账。
- 连接获取不执行建表/迁移/默认账户种子；数据库产品不变也要设计新版结构和版本化迁移。
- 模块化、类型及边界校验、结构化日志、依赖锁定；统一配置与提示词入口。
- 核心验证覆盖指标、规则语义、人工覆盖、有转化保护、权限、幂等、部分失败、未知执行结果及可撤回动作。
- 长任务持久记录并脱离请求生命周期；调度与任务执行分开；不得随多个 Web 进程重复启动调度器。
- 缓存失效覆盖数据/规则/映射/权限相关版本；多进程不能依赖全局字典或线程锁保证共同状态。
- 服务回切与百度端补偿分别设计；同账户/动作仅一套系统真实执行。备份应验证恢复，不能只保存副本。

## 4. 文档职责与决策

RD 管事实、证据与 Q1~Q13；RPD 管功能和 A1~A11 验收；TECH 管推荐、备选及依据；PLAN 管批次和依赖。本文件管授权与安全，不自行扩大业务范围。

最新用户要求优先；历史已确认目标未被明确撤回时，不擅自取消，具体实现未明确时标待确认。技术推荐不等于用户定案；选型依据不等于已经压测。需求冻结先于开发授权，相关增强未定不阻塞原功能设计。


## 5. 线上交付边界

交付目标为线上服务器可部署、可运行、可升级和可恢复的完整系统。开发服务与本地预览不能作为生产交付；部署依赖、持久目录、运行秘密、服务守护、任务单实例、升级与备份恢复须有文档和验证。当前不执行服务器操作，不生成部署配置；服务器条件由 RD Q6 登记。


同机同 IP 部署时，新系统的目录、环境/容器、进程、定时标识、锁文件、Cookie 名、日志和可写数据范围与旧系统隔离。不得占用旧端口、覆盖旧任务或擅自重启旧服务；共享代理或数据库服务需校验路由/逻辑库边界。压力验证、备份与 worker 并发考虑新旧合计资源，不以同机共存作为高可用承诺。


## 6. 增量实施纪律

- 每次一个目标清楚、可独立验证的小步；先说明范围、改动模块、测试和通过标准，不一次铺开整套工程。
- 实现后实际验证；失败先修复，通过前不推进依赖它的下一步，不能留待最后一起测试。
- 每步结束汇报完成内容、验证结果、遗留问题与下一步。继续工作按会话授权，不把每步汇报机械变成索要确认；需新决策或生产操作授权时才停下澄清。
- 对受影响既有能力做必要回归，不未测就连做后续步骤，也不对无关变更重复全量测试。
- 重要状态留可恢复检查点，提交按版本策略；数据备份和外部操作补偿独立于代码提交。
- 用户已授权按小步开始，本次限 S0-01；允许新工程必要版本管理和测试，不授权生产验证或跨步批量实现。
