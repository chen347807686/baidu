## 旧源码事实

keyword_monitor/db.py 的 keyword_daily 主键是 date/user_name/campaign_id/adgroup_id/w_info_id/device；keyword 文本、计划名称及单元名称不属于主键。

keyword_monitor/fetcher.py 的 KEYWORD_UPSERT_SQL 按该主键覆盖指标与名称，重复拉数不是累加消耗；_to_row 将 cost 转为 float、计数转为 int。原表保留六种已知转化与 conv_78、conv_92，后两者用途未明确但不能丢弃。这里核对的是源码定义，不代表已检查实际旧库结构或源数据质量。

## 新增准备入口

prepare_keyword_rows 接收调用方提供的行及显式“源账户名→内部账户 ID”映射，只返回经过校验的候选批次，不执行 I/O、迁移或导入。

- 旧行全部列都必须存在；未知字段拒绝，防止悄悄丢弃尚未核对的来源字段。
- 对象 ID、展现/点击/转化为严格非负整数，拒绝 bool 和数字字符串，不沿用旧版静默转换；未知 conv_78/92 原值保留。
- 内部账户映射要求唯一正整数，不自动创建账户或合并源账户。主键按旧粒度构造；同词不同 ID、不同设备保留；同主键仅改名仍判重复，要求先核对来源。
- 日期转换为 date；词、设备、账户名不修剪，不因清洗擅自改变对象身份。
- 金额采用候选 DECIMAL(18,4) 范围，拒绝超精度、负数和非有限值，不自动舍入。此精度是当前验证边界，正式模型仍需依据真实源值确认。
- float 默认拒绝。显式 allow_legacy_float 时用 repr 得到候选十进制，附原 float.hex 与警告。这仅保留传入浮点值的表示，不证明恢复了百度原始金额，也不授权正式入库。
- 任一行失败不返回部分批次；错误仅含行号/字段名，不回显账户值、整行或输入内容。后续日志仍需受控，不能直接输出候选行对象。

9 项纯合成测试通过：主键粒度、未知转化、重复键、严格类型、日期、金额精度/NaN、未知字段脱敏、浮点核对模式及缺失/非法账户映射。Ruff lint、格式和 mypy strict 通过。新增 Python 文件均有中文模块及流程说明。

没有真实导入 CLI，没有正式事实表迁移或幂等写入，也没有执行完整历史对账。批量入口当前是内存序列，仅用于小批校验；大数据流式分块、跨块重复和任务状态待后续设计。非负计数策略对真实旧数据的适用性仍需验证，若发现调整记录不得静默丢弃。
