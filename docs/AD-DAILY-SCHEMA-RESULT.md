# 统一投放日报结构基础

0013 新增独立 ad_daily，不改变 keyword_daily_v2、现有报表接口和页面。
主键为内部账户、北京业务日期、报表类型、32 字节维度指纹。三种类型分别为
keyword/search_term/creative；设备范围 detail/summary/unknown，设备及其他
完整维度需进入指纹，但本步不生成指纹、不实现来源适配或聚合服务。

字段包括来源映射及版本、项目/计划/单元/关键词/创意 ID、文本、设备、JSON
维度、展现/点击/金额、来源修订与核验时间、内容指纹和入库时间。金额 DECIMAL，
计数非负，未知可空；不得用零替代未知。默认及精确文本排序规则显式声明。
新增来源映射 (id,account_id) 唯一键，事实组合外键确保来源属于同一内部账户。
名称不参与主键；不存线索/预约展开消费，避免以后关联时重复累计。

本步只验证结构，不能宣称已实现“不混加”查询策略：数据库允许三类、设备
明细与汇总同时存在，后续查询必须选定类型与设备口径。指纹规范版本、NULL
聚合完整性、幂等覆盖、来源核验新旧顺序及写入预算仍由后续服务实现。
PK 不含 source_account_id，当前默认一内部账户的同类投放不会来自多个独立
重叠来源；来源适配前必须确认该约束，不允许静默覆盖不同来源。

实际在随机隔离库验证类型/设备独立行、NULL 与 0 区别、重复键、状态大小写、
金额/计数非负、版本约束、跨账户来源拒绝，及非空阻断降级、空表回退再升级。
模型/迁移漂移与现有权限等一起回归；全套 103 项测试通过，Ruff、格式及
mypy strict 通过。运行库未执行 0013，未连接百度，无真实数据导入。
