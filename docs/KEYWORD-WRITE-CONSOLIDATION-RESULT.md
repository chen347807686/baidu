# 关键词写入入口收敛

## 本步变更

`keyword_store.write_keyword_rows(conn, rows)` 成为正式日报唯一的逐行 UPSERT
入口，统一完整候选校验、主键排序和覆盖写入规则。它接收调用方 Connection，
不自行开启、提交或回滚事务，也不吞掉数据库异常。

`store_keyword_batch` 仍负责直接小批次的事务，保留连接前校验和空批不连接数据库；
共用入口再次校验，避免单独调用时绕过校验。`apply_plan` 继续负责计划锁定、
指纹核对及完整事务，将事实写入与计划成功状态共同提交。重复确认成功计划仍
直接返回原结果，不再写事实。每批上限、覆盖语义、金额核对和账户改名保护不变。

## 验证

- 全套隔离 MySQL 测试通过：79 passed。
- 新增外层事务后续失败回归：共用入口成功执行的金额更正仍随外层事务回滚。
- 原有确认入库测试继续覆盖第二行失败时事实与计划状态同时回滚、重试成功、
  重复执行幂等，以及文件/数据库变化拒绝。
- Ruff 检查、格式检查及 mypy strict 均通过。

## 边界

本步没有迁移或运行库数据写入，不调整逐行写入策略，不引入网页导入入口。
数据库异常的脱敏诊断日志留到下一步，生产性能仍需独立评估。
