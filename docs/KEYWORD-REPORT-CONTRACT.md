- 日数据先按日期、账户、计划 ID/名称、关键词文本聚合。

- 账户集合排序；计划数量按计划名称去重，展示排序后的前五个名称。不同账户同名计划可能被合并，纠正须单列，不静默改口径。

## 2. 指标基线

先合计原始量，再计算派生指标；不能平均每行成本或转化率。

| 字段 | 计算 |
|---|---|
| lead_total | conv_form + conv_lead + conv_dial + conv_wechat |
| consult | conv_1sent + conv_3sent |
| lead_cost | cost / lead_total，2 位小数 |
| s1_cost / s3_cost | cost / 对应咨询量，2 位小数 |
| dial_cost / form_cost | cost / 对应转化量，2 位小数 |
| consult_rate | consult / click，4 位小数 |
| lead_rate | lead_total / click，4 位小数 |
| cpc | cost / click，4 位小数 |

分母为零返回 null。底层保留原始转化字段，未知 conv_78/92 不因未展示而丢弃。MySQL DECIMAL 精度、原始金额来源和舍入策略必须在真实导入前确认；旧 Python float round 不能当作金额无损证据。

固定样例：两条同词数据，消耗分别 100、50，点击 10、5；表单合计 1、留线索合计 1、拨通合计 1、加粉合计 0，一句话合计 3、三句话合计 0。预期合并一行，cost=150，click=15，lead_total=3，consult=3，lead_cost=50，consult_rate=0.2，lead_rate=0.2，cpc=10。另加无权限账户同词记录时，以上值不得变化。

## 3. V2 接口草案

GET /api/v1/reports/keywords；原接口暂未替换。

请求：start/end、account、department、person、category、search、sort、order、page、page_size。日期缺省规则保留；只给一端、日期倒置、非法分页或排序字段建议返回 422，区别于旧版静默兜底。默认范围按 Asia/Shanghai 计算。最大日期跨度依据 Q4，未先设任意业务上限。

响应：rows、total、page、page_size、summary、applied_filters。total 是过滤后关键词文本组数；summary 为整个筛选结果的合计，不是当前页合计。金额建议使用十进制字符串，具体响应模型实施时固定并测试。

服务端先从已认证身份取得允许账户集合，再与请求账户、归属筛选取交集；客户端不能提交允许账户集合来替代身份认证。未登录 401；明确请求无权账户 403；无授权账户时结果为空，不回退为全账户。

SQL 中完成权限过滤、业务过滤、聚合、稳定排序和分页。排序字段白名单；值参数化。相同排序值用关键词文本的确定性次序打破平局，空值最后。文本分组和搜索必须验证 MySQL 排序规则对大小写、重音、全半角和尾随空格的行为，不能只凭 utf8mb4 假设与 Python 等价。

数据量、权限与总数必须使用同一口径；并发写入时的快照一致性需在查询实现中处理。第一页、第二页无重复/遗漏只在同一数据版本下验收。

## 4. 必须落地的验证

1. 同词跨账户/日期聚合、不同词分离，中文和大小写/空格边界。
2. 固定样例指标、零分母、合计后计算比率、金额精度与舍入边界。
3. 权限先于聚合：无权账户不能进入列表、汇总、总数、账户或计划展示。
4. 默认日期、双端日期、非法范围、非法排序和分页。
5. 字面搜索包含百分号、下划线及 SQL 注入字符串，作为普通输入处理。
6. 同值稳定分页、空值末尾、0 不视为空值、越界页 rows 为空而 total 不变。
7. 人员/部门映射与分类筛选对账，不能只给旧 SQL 添加 LIMIT。
8. 查询路径在 MySQL 验证，不使用 SQLite 结果替代目标数据库证据。
