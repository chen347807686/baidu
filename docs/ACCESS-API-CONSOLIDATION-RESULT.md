# 规范收敛第三步：权限查询 API 与认证常量

2026-11-10。收口公开查询契约，并同时修复已确认的身份参数隐式转换问题。

## 入口和类型边界

- visible_account_ids(user_id) 返回单列 Select[int]，专供 IN 子查询、权限过滤；不暴露账户名称，也不要求调用方操作权限模块内部 Table。
- visible_accounts(user_id) 保留双列 (id,name) 与原排序，仅用于展示。双列不是本身错误，但不能再当单列子查询；文档明确区分。
- 两者复用私有策略函数，表引用在权限模块中使用私有名称。报表只调用 ID 入口，不再自行 with_only_columns 或引用 access.accounts。
- 在构造 SQL 前要求 type(user_id) is int，拒绝 bool、数字字符串、带数字前缀文本、浮点数和 Decimal，超出 access_users.id 的有符号 INT 范围也拒绝。错误不回显输入。
- 保留负整数这一数据库可表达类型，兼容独立测试样本；不存在的正/负 ID 都没有可见账户。身份依然必须来自服务端认证，不因为类型合格就允许客户端指定用户。

## 常量归属

Cookie 名称统一到无路由依赖的 auth_constants.py。认证接口、报表和测试直接引用中立模块，不再由 reports 依赖 auth_http 来取得常量。值仍为 onetitle_v2_session，属性由 HTTP 层负责，本轮不清理或撤销已有会话。
