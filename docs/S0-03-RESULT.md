# S0-03：可配置账户可见范围

日期：2026-11-10。用户批准“竞价员本人、主管本部门、管理员全部；未分配仅管理员”及可调整授权设计。

## 已实现

- 0002 迁移：部门、用户、账户、单独账户授权、主管额外部门授权，共五张表。角色有约束，关系有外键，重复授权由联合主键阻止。
- 用户角色和部门、账户负责人和部门均存数据库；更改这些配置不需要修改策略代码。账户部门单独维护，不因负责人调部门而自动改变。
- 统一 visible_accounts 查询可作为报表子查询或关联条件，用于聚合/分页前隔离；不在 Python 加载所有报表后才过滤。
- 单独授权仅扩大已分配账户范围；未分配指 owner_id 为空，哪怕存在部门或额外授权仍只有管理员可见。
- 竞价员只按本人归属及单独授权；主管按本部门、额外部门及单独账户授权。额外部门授权对竞价员不生效。
- 不存在、停用、未知角色均无可见账户；管理员停用也不例外。
- 所有新 Python 文件含中文文件说明，关键规则有中文注释。

9 项测试通过，含真实 MySQL 权限矩阵：跨部门限制、未知用户、额外账户授权/撤销、多部门主管、降为竞价员、账户转交、管理员停用、未分配账户保护。合成数据在事务结束时回滚，不保留示例人员。已有健康、配置脱敏、迁移重复执行、应用账号禁止建表测试通过。

Ruff lint、格式检查、mypy strict 通过。沿用 TestClient 的 httpx 弃用提示，未影响结果。

## 生效边界与后续

策略不缓存权限，每次执行读取数据库。调用方必须按请求开启新事务；MySQL 长事务的旧快照可能延迟其他事务已提交的变更。当前验证覆盖同事务修改后的重新查询，跨请求/并发撤权将在认证与请求生命周期实现时补充，尚不能宣称完整系统已验证即时撤权。

本步交付持久结构和查询策略，尚无登录、会话、权限配置页面或管理 API。user_id 是内部策略参数，只允许来自后续服务端认证结果，不能用客户端任意 ID 作为身份。当前没有暴露此查询的 HTTP 入口。权限修改的服务端管理限制及审计、敏感操作权限与审批需后续实现，数据库应用账号的 DML 能力不代表用户可修改授权。

新增角色或改变默认规则需要修改集中策略并测试，已有角色归属及授权范围通过数据配置调整。当前本机库仅有结构，无真实账户或默认管理员。
