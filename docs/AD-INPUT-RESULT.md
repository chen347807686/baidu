# 投放输入准备与维度指纹 v1

新增纯函数 prepare_ad_rows，接收规范化行列表，全部校验通过才返回 PreparedAd。
不连接数据库/百度，不读取文件；没有 HTTP 入口或实际写入。准备上限 1000 行，
不是写入事务预算。可空字段仍需显式提供，避免漏列被当作未知；空批返回空列表。

## 输入与实际使用

输入字段对应 ad_daily，但 grain_key/grain_version/content_hash/dimensions 由
准备层生成，调用方提供 extra_dimensions 而非自行传指纹。日期接受 date 或
严格 YYYY-MM-DD；时间必须为带时区 datetime，转换为无时区 UTC 供 MySQL 写入。
金额只接受 Decimal、十进制字符串或整数，拒绝 float/bool、非有限值、负数、
超范围或需舍入的小数；无效尾零允许。计数、ID 严格整数，未知指标必须为 None。

关键词报表要求 keyword_id，创意要求 creative_id，搜索词要求非空 search_term。
设备明细要求设备值，汇总设备为 None，原始汇总代码可作为扩展维度保存。
unknown 不被猜为汇总。扩展维度仅扁平标量：str/int/bool/None，最多 32 个，
拒绝 float 和嵌套，保留类型、大小写与首尾空格。来源接入前需核对这些约定。

异常 AdInputError 提供 row/code/fields，行号从 1 开始，批次超限用 0；
invalid_record、invalid_encoding、duplicate_grain、batch_too_large 为固定错误码。
只返回模型已知字段，不复制任意额外列名或输入值。组合规则错误可能没有单字段，
调用方应按行提示，不打印底层 Pydantic 异常。

## 指纹契约

维度使用 schema_version=1、报表类型、各实体 ID、设备及范围、扩展维度，
搜索词类型额外包含精确搜索词。固定排序 UTF-8 JSON 后 SHA-256，存 32 字节。
关键词/物料名称与指标不入维度；账户、日期在表主键中单独存在。
NULL/空串/扩展字段缺失、bool/int/string 不合并；相同规范数据不受字典顺序影响。
同批完整事实键重复直接拒绝，即使来源映射或指标不同也不静默覆盖。

content_hash 包含规范身份、展示信息、指标及来源绑定，排除来源修订与核验/入库
时间；重复核验不会制造业务内容变动。金额统一四位文本后计算。
PreparedAd 内部存不可变 JSON 字节；parameters() 每次返回独立数据库参数，
恢复日期、Decimal 和 UTC 时刻。可写字段集合与现有 ad_daily 结构核对。

## 验证与限制

新增 19 项纯回归，覆盖名称/指标更正、设备/类型/搜索词差异、字典顺序、类型
区别、金额边界、漏指标、重复事实、错误脱敏、不可变结果及批次上限。
全体非数据库测试 102 passed、20 个数据库测试明确跳过；本步未改数据库结构、
查询或写入，不重复运行集成数据库。Ruff、格式和 mypy strict 通过。

仍需来源适配器确认完整身份维度：本层不能自动识别漏维度，也不验证内部账户
是否存在、映射是否启用/属于账户或不同来源是否重叠；后续写入事务必须检查。
本步不提供混加查询，不证明 unknown 指标完整；下步受控写入需处理完整维度
碰撞比较、新旧修订、NULL 覆盖、映射版本与小批事务预算。现有报表继续使用旧表。
