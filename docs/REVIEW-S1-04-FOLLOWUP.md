## 已处理：测试隔离

原测试共用 onetitle_v2_local，test_manage 依赖空凭据库，管理员可见范围断言也依赖样本独占。其结果是本地真实账号或并发测试会污染验收，属于必须解决的工程缺陷。

tests/conftest.py 给每个 mysql 标记的集成测试创建随机独立数据库、迁移账号和仅 DML 应用账号，测试从空库升级。测试只接受 local_mysql.py test 显式传入的测试管理员密码，服务器目标固定 127.0.0.1:13306，不读取 ONETITLE_DB_* 的运行目标。未显式启用时跳过数据库集成测试。

普通结束会删除本次成功创建的随机库与账号；资源名称严格校验，创建失败不删除既有资源。独立库名与账号使用随机值，可同时运行多套 pytest，不依赖固定负数样本跨测试唯一。

test_keyword_store 不再假设账户 2147483647 不存在：在本测试库分配一个账号后删除，以它的 ID 验证外键失败。原写入事务和业务实现不变。

强杀进程仍可能留下随机测试资源，这是 finally 的客观限制。残留只存在 tv2test 随机库，后续测试不会复用，不能污染本地运行库。没有自动扫描/删除其它测试或个人数据库；需要清理时应核对具体资源归属，不按前缀盲删。

## 业务待确认：源账户改名

旧主键含 user_name，新主键含内部 account_id。源账户改名但映射到同一内部账户时，新模型会按相同对象键覆盖，不能无条件宣称与旧历史行数一致。

此项须明确“稳定百度账户身份、别名/改名历史、旧行是重复快照还是应保留事实”。真实快照迁移前纳入 Q8 对账决定；当前不改主键，不读旧库，不执行真实导入。保留 user_name 字段不等于保留了旧主键下的全部历史记录。

## 按需评估：关键词索引

正式表已有 (account_id,date) 索引。查询是否扫描全表取决于 SQL、权限账户范围、日期跨度、基数与优化器选择；缺少 keyword 索引本身不能直接推出必然全表扫描。

按词聚合可能仍需临时表或排序；包含搜索通常不能简单依靠 B-tree 前缀索引解决。待正式查询链路与代表性数据明确后检查 EXPLAIN/耗时，比较索引、维表或预聚合；本次不凭猜测加索引，也不宣称已完成性能验证。

## 保留旧语义：空设备

旧 db.py 的 device 为 TEXT NOT NULL DEFAULT ''，fetcher.py 将缺失设备归为 ''。新迁移中 device 属于主键，SQL NULL 已禁止；接受空字符串是另一回事，目前与旧默认语义一致。

如需将空字符串解释为“未知设备”、区分“全设备合计”或拒绝缺失值，必须先核对百度报告来源，不直接增加非空字符串约束。
