# 导入数据库错误脱敏诊断

## 处理范围

直接小批次写入与本机导入 CLI 的 plan/apply/status 数据库失败路径共用
`database_diagnostics.report_database_error`。不输出底层异常原文，改为根据
数值 MySQL 错误码提供结构、权限、约束、锁冲突、连接或未知错误提示。

诊断只记录固定操作名、SQLAlchemy 内置异常类别、四位数值错误码，以及驱动
提供且符合五位大写字母/数字格式的 SQLSTATE。PyMySQL 不提供 SQLSTATE 时
显示 None，不通过解析异常消息补造。日志不包含 SQL、参数、源数据、密码、
连接地址或异常堆栈；调用方仍不能擅自打印原始异常。

## 查看方式与提交边界

默认使用 Python 标准日志，由本机维护命令的标准错误显示诊断；普通操作结果
仍在标准输出。未配置文件持久化或全局日志，不会自动建立可能包含运行信息的
日志文件。服务宿主以后可以统一接管这个具名 logger。

错误分类提供排查方向，不能证明提交结果。尤其连接中断时，仍须通过计划 ID
查询状态，直接批次则按主键读回核对。未引入自动重试，不改变事务边界。
仅覆盖上述两个导入入口，其他认证/预览/维护入口不在本步统一范围内。

## 验证

新增 11 项纯回归，覆盖错误分类、非法诊断字段丢弃、SQL/参数/异常内容脱敏、
直接写入业务异常，以及三个 CLI 操作失败时的诊断、提示和连接释放。
完整隔离 MySQL 测试 90 项通过；Ruff、格式检查和 mypy strict 通过。
测试使用合成数据与独立库，未修改运行库数据或原始项目。
