# RPD — 投放监控看板重构需求

版本 v0.8 · 2026-11-10。范围决策见 RD 第 7 节；技术推荐见 TECH。

## 1. 目标与分类

以旧版为业务参考，保留有效能力，改进查询性能、操作体验、可靠性、安全和可维护性。历史“替代人工拓词”的业务目标保留，其首批优先级和实现范围待确认。

- 保留：现有能力重建，保持已核实语义，不要求复制旧代码或全部接口。
- 改进：针对已有缺陷补强；新增技术组件不能自行变成新业务范围。
- 增强待确认：自动种子、统一建议队列、直接加词、效果评估等，分别选择。
- 范围外：易聊/CRM、预约到店、团队绩效、小时报、AI 素材生成、站内消息、独立运维门户。

建议 P0：原核心功能、性能、核心界面、权限与操作保护、任务可靠性。P1：额外交互和可视化优化。P2：暗色、移动和大屏。批次可讨论，AGENT 的安全与数据保护底线不可通过降低优先级省略。

| 目标 | 内容 |
|---|---|
| O1 | 保留拓词种子、推荐、评分、筛选、采纳/忽略/导出 |
| O2 | 减少人工拓词工作量；增强实现和首批目标见 Q11/Q13 |
| O3 | 改善报表、筛查、预警、拓词的任务路径；队列独立评估 |
| O4 | 保留报表、筛选、历史、差异与导出，并保证口径 |
| O5 | 重做核心页面与前端结构，不靠凑图标/图表数量验收 |
| O6 | 权限、操作保护、审计、任务及发布可维护 |
| O7 | 保持子系统边界 |
| O8 | 通过约定场景的响应时间、并发与数据正确性验收性能 |

### F03 保留细节

规则保存不自动覆盖历史；应用前预览，可撤销且不覆盖人工结果。自定义否词保留包含/精确、作用范围、批次撤销，历史上限 5000 词在冻结时复核。评分原权重为合规 30、意图 25、搜索量 20、竞争 15、CPC 10。自动选种子、偏好学习和自动改阈值另议，不以重构名义改变规则。

### F07 写操作

F07-1 预览对象、账户、变更、风险和有效期；F07-2 人工单条或明确明细的批量确认；F07-3 原暂停/否词，直接加词待 Q11；F07-4 写后逐项读回、异常告警和结果记录；F07-5 区分本地撤销、远端反向动作和不可逆影响；F07-6 高风险审批 Q3；F07-7 操作人/时间/前后值/结果审计；F07-8 幂等、部分失败、超时未知结果和重试保护。

高风险动作未明确审批规则时不开放；审批或确认后对象/参数变更需重新校验。暂停后恢复投放属于反向操作，不能承诺挽回暂停期间的流量。自动执行须另有决策。

### F09 工程基础

F09-1 身份/会话；F09-2 服务端账户授权；F09-3 外置凭据与受控轮换；F09-4 历史资产保留/导入/归档；F09-5 版本与发布恢复；F09-6 持久任务、重试、完整性及失败通知；F09-7 统一配置、校验及环境隔离；F09-8 提示词版本与评估；F09-9 模块化、类型、日志、依赖锁定和关键验证。

环境/凭据、业务配置、提示词分别管理。运行数据库可存受控业务配置、脱敏调用记录及审计；真实凭据、敏感账户内容和运行日志不得进入版本仓库或代码交付包。

## 4. 数据、性能与角色

- 口径按 RD 第 5 节；稳定对象 ID 与词文本分开，唯一键按日报真实粒度定义。
- 明确负责人映射按“当前归属”还是“历史生效日”解释，先保持旧可验证行为；变化需版本和对账。
- 优先消除应用层大结果合并/筛选/排序/分页和重复请求；分区/缓存/预聚合等按 TECH 评估。
- Q4 明确首屏、查询、分页、切页签、导出和拉数的范围/跨度/数据量/并发/冷热缓存、P50/P95 和失败率，不把历史遍历耗时当 SLA。
- 区分零数据、未拉取、失败与部分完成；T+1 的具体到数截止时间由 Q4 确认。
- 历史资产保留，不等于一次性全量进新主库；未知字段原值保留。对账含映射版本、回补、金额精度和舍入。
- 竞价员、主管、管理员、运维的具体权限 Q3；运维不默认读取全部业务数据，无人归属账户有明确处理规则。

## 5. 视觉

V1 统一图标语义；V2 清晰导航与筛选/下钻，首页 Q2；V3 决策所需趋势/对比/构成，队列漏斗按所选增强；V4 统一颜色/间距/字号、¥、涨红跌绿并注明指标好坏；V5 加载/空态/错误/重试/数据过期；V6 组件化与请求管理；V7 暗色/移动/大屏后续。

核心页面和状态反馈优先，辅助图表与动效后置；不设图表数量门槛。

## 7. 线上部署要求

与旧系统同机、同 IP 部署，新旧入口隔离，可使用不同端口或路径；不要求替换原完整 URL。前端交付构建产物，API、worker 与定时入口按 TECH 的职责分别运行；数据库、运行配置、日志与备份独立于可替换的代码版本。进程退出及服务器重启后可恢复服务，提供健康检查、任务状态和受控访问。升级具备结构迁移、备份、验证与回滚步骤；服务回切不等于数据库或百度操作回滚。具体域名、HTTPS、网络边界、操作系统及资源见 Q6。


新系统使用独立发布目录、配置与凭据引用、服务进程、运行日志及数据存储；数据库可用同一数据库服务中的独立逻辑库/角色，不强制另起数据库实例。端口须检查占用，CPU/内存/连接数/任务并发和磁盘容量须覆盖新旧合计负载；部署、升级和压力验证不得挤占旧系统正常运行。


## 8. 增量验收

每次交付一个可独立检查的小步，先写范围和验收。基础工程验证启动、健康与配置；业务验证口径和边界；接口验证输入、响应、权限；数据变更验证迁移与对账；页面验证交互和联调；百度写入先模拟或在隔离环境测试，真实写入需相应授权。每步留验证结果，检查受影响的已完成能力；不要求每步重复全量测试，不为无关文件机械补测试。最终仍须集成验收。
