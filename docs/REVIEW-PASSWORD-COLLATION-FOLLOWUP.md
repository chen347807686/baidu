# 密码与正式日报排序规则复核修复

2026-11-10。先处理本轮两项正确性问题，写入去重、错误诊断和性能项另列后续，不混入其它业务建设。

## 1. 历史短密码升级

问题确认：旧短密码可以通过旧参数验证，但登录升级调用公开 hash_password 的新密码最小长度校验，导致 ValueError/HTTP 500。

修复：公开 hash_password 仍要求 12–128 位，调用私有重哈希实现；只有登录完成旧密码验证并确认账号启用后，才直接调用私有实现升级既有密码。私有路径保留最大长度、编码和参数保护，不强制新密码最小长度。没有用“吞掉 ValueError 跳过升级”的方式掩盖错误，也没有放宽注册/重置策略。

真实 HTTP 测试独立生成 100000 与 599999 轮、六位密码记录：错误密码 401 且不改哈希；正确密码 200，原参数升级至当前值；升级后再次登录仍为 200；当前用户接口正常。公开新建和 reset 服务仍拒绝同一短密码，拒绝后哈希不变。实际管理员没有参与测试或被重置。

## 2. 表默认与名称列排序规则

问题确认：0007 只指定 mysql_charset 时，正式表默认实际为 utf8mb4_0900_ai_ci，两列名称继承该值；仅核对显式列 collation 的测试遗漏了默认值。

新增 0010，不改 0007：单条 ALTER 设置正式表默认为 utf8mb4_0900_as_cs，并明确 campaign_name/adgroup_name 两列同样规则。未使用全表 CONVERT TO，keyword/device/user_name 的 utf8mb4_0900_bin 不变；不归一化或清洗名称文本。共享 schema 同步表级 mysql_collate 和两列规则。

漂移测试新增模型显式配置的表默认 collation 核对；专用默认 ai_ci 的隔离库测试验证升级前实际 ai_ci、升级后表默认/两列 as_cs、三列 bin 保持、大小写/重音不同不相等，以及 0010 降级不影响 0009 角色安全结构。该项没有新增按名称筛选功能，未来仍需按具体业务验证完整查询口径。

本机独立库已升级至 0010，读回表默认 as_cs，角色列仍 bin。前后用户角色/启用状态、会话数量及正式日报数量一致，无线上或旧库操作。0010 降级恢复此前名称比较规则，不删除事实记录；正式使用后的查询语义回切仍需评估。
