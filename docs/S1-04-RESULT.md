# S1-04：正式关键词日报表与幂等写入

2026-11-10。本步创建 V2 独立正式事实表与后台写入服务，仅通过合成数据验证，没有读取或导入旧库。

## 实现

0007 创建 InnoDB keyword_daily_v2，主键为 date/account_id/campaign_id/adgroup_id/w_info_id/device。设备使用 utf8mb4_0900_bin，避免大小写或尾随空格被合并；账户引用 access_accounts。保存源账户名、计划与单元名称、词文本、展现/点击及全部八类转化（含 conv_78/92）。源对象 ID/计数为非负有符号 BIGINT，金额 DECIMAL(18,4)，账户日期有索引。

金额精度仍是当前准备契约，不意味着已确认全部真实金额适配；正式导入前需核实来源与差异。模型不保存原始 API 机密响应或凭据。

store_keyword_batch 仅供受控后台调用：重验证候选、限制每批 1000 行、拒绝重复主键及超存储范围文本。浮点来源或带警告的核对候选一律拒绝正式写入，不能仅通过允许准备阶段浮点就入库。

固定列名和参数化 SQL；同键 upsert 覆盖名称/指标，不做金额累加。按主键排序降低锁顺序冲突，整批事务提交；中途数据库失败回滚，错误不回显 SQL 参数。processed 表示已提交输入键数，不是新增行数。零行不连接数据库。

服务自己管理事务，调用方不能把此函数与其它写入误认为同一原子事务。提交阶段网络断开可能产生未知提交结果，须按主键读回确认，不能仅凭异常宣称绝对未写入。并发批次尚无来源版本优先级或防止旧快照覆盖新快照的策略；本步不开放并发采集或生产导入。

11 项相关测试通过（正式写入、输入准备、迁移与数据库边界），Ruff lint、格式、mypy strict 通过。新增测试使用动态分配的合成用户/账户并最终清理，验证管理员不变。既有测试隔离问题未混入本步修复，未声称全套测试通过。
