# K1：关键词质量与否词判定契约

2026-11-11。状态：可审阅方案与固定验收样例，尚未实现，不代表业务阈值已经确认。需求与决策分别以 RPD 第 9 节、RD 第 7 节为准。本文为 K2 的输入，不修改数据库或旧系统。

## 1. 参考依据与判定对象

旧项目 `keyword_monitor/expansion.py:list_seeds` 默认从有至少一次综合线索的词中选种子，默认窗口 90 天；`keyword_research/quality.py` 使用 A/B/C/D/F 分级。本主线只保留“命中否词/未命中/待复核”，不引入相关、不相关、边界分类。

建议首版不引入新的综合分权重：原词根据真实表现判断质量，拓展词只展示模型理由和否词规则结果，真实表现未知时保留未知。旧行业词库及 85/70 等等级阈值不自动移植。

工作台按“账户 + 原词来源身份”呈现判定对象，同文不同账户、不同来源对象分别记录。已有报表仍按原口径汇总，不能将其跨账户汇总行直接作为标注对象。用户必须能展开或选择明确的账户/对象，再提交标注和拓词；不暗改现有报表聚合接口。

## 2. 三类独立状态

| 维度 | 状态 | 语义 |
|---|---|---|
| 质量 quality | pending / ordinary / high | 待判断 / 普通 / 优质；无数据不是普通 |
| 否词 negative | unknown / suggested / confirmed / clear | 未判定 / 建议否词 / 已确认否词 / 非否词 |
| 候选审核 review | pending / adopted / ignored | 待审核 / 采纳 / 忽略，仅针对拓展候选 |

每个可人工调整的维度分别保存自动建议、人工覆盖、最终值及版本。最终值优先取该维度人工覆盖；重跑只更新自动建议，不覆盖人工值。取消人工标记是撤销覆盖，显示最新自动建议；不是删除历史，也不是一律改成“非否词”。

否词 clear 表示在记录的账户、对象与范围内判为非否词，不是全局白名单。质量 high 不清除否词状态；采纳不改变质量或否词；忽略不等于不相关或否词。

## 3. 原词质量规则建议 v1

输入：明确的账户/对象、起止日期、数据完整性、消耗、点击、四类线索、相关性、适用否词证据、规则版本。综合线索沿用 `conv_form + conv_lead + conv_dial + conv_wechat`，不是去重客户人数；conv_78/92 不加入。先合计后计算成本和转化率，零分母为空。

建议采用以下可解释规则，按顺序匹配。自动结果与人工覆盖独立：

1. 来源缺失、窗口不完整、核心字段未知或配置不完整：pending，说明缺少的证据。已有日报记录不能单独证明整个窗口已完整获取。
2. 已确认否词、规则命中冲突或否词状态尚未复核：pending，附冲突原因，不自动推荐为种子。有转化时仍保留真实表现，不删除或改写指标。
3. 规则判定通过、数据完整，点击达到 C，综合线索达到 L，线索成本不高于 T：high。
4. 规则判定通过且数据完整，但点击不足 C：pending，即使有一次转化也说明样本不足。
5. 规则判定通过且数据完整，点击达到 C，但线索或成本未满足：ordinary。零线索时成本为空，用“线索不足”解释，不与 T 做空值比较，不自动建议否词。
6. 规则输入不足或规则结果不明确：pending，先补规则所需证据，不仅凭词面或点击直接判为优质。

| 参数 | 推荐处理 | 当前状态 |
|---|---|---|
| 观察窗口 | 首版建议截至北京时间昨天的最近 30 个完整自然日；可查看 90 天作为辅助，避免混用窗口 | 建议，未确认为默认 |
| C 最低点击数 | 按账户配置正整数；用固定样例验证边界，不把任意数字当行业标准 | 待确认 |
| L 最低综合线索 | 至少为 1；旧项目的 1 可作初始参考，需结合最低点击样本 | 待确认 |
| T 目标线索成本 | 按账户配置正数金额，不采用跨账户统一成本线 | 待确认 |
| 数据完整性 | complete / partial / unknown；由来源覆盖证明，不以缺行补零推断 | 需在 K2 对接设计中落实 |

配置不足时自动质量为 pending，仍允许在明确对象上有理由地人工标优质。人工优质展示“人工判断”，不伪称达到自动阈值。未定参数不阻塞 K2 的独立存储设计，但阻塞自动质量规则在真实账户启用。

## 4. 否词匹配与人工操作

建议首批人工标注作用于明确原词/候选，不直接新建包含匹配规则。词库规则另带账户、词类型（关键词或搜索词）、账户/计划/单元范围、精确/包含匹配及版本；各限制同时满足才算命中。缺少所属计划/单元时，不能把局部规则当全账户命中。

精确匹配按原文本精确相等，包含匹配按原文本包含；首版建议不自动折叠大小写、全半角或内部空格，导入解析与原文本分别保留。具体兼容口径在 K2 测试固定，不能只依赖数据库默认排序规则。

自动匹配和模型输出只能给 suggested，带命中词、匹配方式、范围、规则或模型版本；confirmed/clear 来自明确人工操作。若已有人工 clear 而新规则建议否词，保留 clear 并提示冲突。已有 confirmed 不被模型 clear 或质量 high 自动解除。

有转化或优质与否词冲突时，标注 confirmed 需展示证据并要求填写复核理由；仍仅保存内部记录，不调用百度。批量确认也逐对象验证，任一对象有冲突或版本过期则整批拒绝，刷新后重新审核，不静默跳过。

操作记录包含人员、对象、范围、时间、理由、前后值、自动/人工来源及版本。客户端带预期版本，版本不符返回冲突；服务端检查当前身份及账户权限。批量单次建议最多 100 个明确对象，界面说明选中数量和账户，不默认全选筛选结果。

## 5. 拓词种子资格与来源追溯

建议种子条件：最终质量 high、否词状态 clear、无未复核冲突，且用户有该账户权限。否词 unknown 先完成检查；suggested/confirmed 不允许直接提交。人工高质量但真实数据不足可以在满足其他条件时作为人工种子，任务快照注明证据不足。

创建任务和 worker 实际调用前均校验资格与版本，条件变化的种子标为跳过待复核，不继续调用。模型调用期间发生新标注时，保留已产生结果及快照，在结果中提示来源变更并阻止直接批量采纳。模型生成不修改原词标签。

每个候选保留所有来源种子 ID 和任务快照；同文候选只在同账户、同任务内按明确文本口径合并，多账户不得合并。跨任务历史去重仅作历史提示，不能丢失本次来源。原词后续改名或删除仍能查看任务时文本和身份；访问历史来源仍须验证当前账户权限。

## 6. 固定验收样例

以下全部为合成数据。仅为测试设 C=20、L=2、T=100 元；不是产品默认。除特别说明外，账户 A、规则判定通过、否词 clear、窗口完整且无人工覆盖。

| 编号 | 输入或操作 | 预期 |
|---|---|---|
| J01 | 点击20，线索2，消耗200 | high，线索成本100，允许选种子；覆盖等号边界 |
| J02 | 点击19，线索2，消耗100 | pending，样本不足；不自动选种子 |
| J03 | 点击20，线索1，消耗50 | ordinary，线索不足；不是否词 |
| J04 | 点击20，线索0，消耗200 | ordinary，线索成本null；不是否词 |
| J05 | 点击20，线索2，消耗200.0001 | ordinary，成本高于目标；判定使用未展示舍入的精确比值 |
| J06 | 数值满足J01，但窗口partial或unknown | pending，数据不足；不补零或伪造完整性 |
| J07 | 数值满足J01，缺T配置 | pending，配置不足 |
| J08 | 数值满足J01，规则结果不明确 | pending，需复核；不自动标否 |
| J09 | 人工high，自动重跑ordinary | 最终仍high，自动建议更新，人工理由与历史保留 |
| J10 | 在J09取消人工质量覆盖 | 最终ordinary，取消操作追加审计；否词状态不变 |
| J11 | 数值满足J01，但人工confirmed | 保留表现和人工否词，提示冲突，禁止作为种子 |
| J12 | 人工clear，新词库规则命中 | 最终仍clear，显示冲突，复核前不可作为种子 |
| J13 | 已有转化词确认否词但缺少复核理由 | 拒绝本次更改；有理由复核后仅保存内部confirmed |
| J14 | 账户A与B同文，A优质、B普通 | 分别保存；仅有A权限者看不到B的状态、来源或指标 |
| J15 | 计划P1包含否词规则，词对象在P2或计划未知 | 不判定为P1命中；计划未知时提示范围待核实 |
| J16 | 用户只选当前页3词，筛选结果共500词 | 仅3个明确对象参与；页面切换清空选择或明确保留策略 |

| J19 | 批量100词中1词越权或预期版本过期 | 整批拒绝且无部分改写；返回安全错误，不泄露越权对象内容 |
| J20 | 新候选无真实投放数据，模型称高转化 | 实际点击/线索/成本均未知；模型理由仅作建议，不能自动成为表现优质词 |
| J21 | 线索2、消耗200、点击0 | 指标冲突待复核，pending；不伪造点击或转化率 |
| J22 | 提交后原词由clear改为confirmed | worker调用前拦截；已调用结果保留快照、显示变更并要求复核 |

输入中缺核心指标、负数、非有限金额或“有线索但零点击”等异常先进入数据校验/复核，不进入正常质量分支。成本阈值比较采用 Decimal 精确比较（如 cost <= T × leads），不以两位展示值判断。
