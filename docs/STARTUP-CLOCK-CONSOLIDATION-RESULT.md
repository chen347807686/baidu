# 启动配置与限速时钟收敛

## 本步变更

命令行启动读取一次已校验 Settings，传给 create_app；Uvicorn 监听与认证
来源端口使用同一份配置。create_app 保留无参数调用兼容性，此时自行读取
配置。数据库配置仍由原有统一入口按认证开关读取，没有新增全局配置对象。

应用工厂和认证路由支持显式注入限速时钟，默认使用系统时间。HTTP 集成测试
改用各应用实例的固定时钟，不再 patch time.time，避免影响日志、会话和其他库。
consume_attempt 每次仅读取一次时间，分钟窗口与 Retry-After 使用同一时刻。
会话有效期和数据库 UTC 时间处理保持原样；成功登录计入限速的现有规则不变。

## 验证

- 启动回归：应用工厂重读配置会直接使测试失败，验证启动仅加载一次配置，
  并将其端口、地址用于监听。
- 分钟边界回归：119.9 秒对应窗口 1、重试 1 秒，120 秒进入窗口 2。
- 真实 MySQL HTTP 回归：两个应用实例注入同一固定时钟后仍共享数据库限速。
- 完整隔离 MySQL 测试 96 项通过，Ruff、格式检查及 mypy strict 通过。

本步没有修改运行库、已有账号或密码，不涉及部署。固定窗口的边界突发与
系统时间调整仍是现有策略限制；生产限速设计及密码计算性能需单独评估。
