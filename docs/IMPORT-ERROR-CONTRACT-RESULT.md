# 导入预览错误契约与提示收敛

## 变更

`KeywordInputError` 增加稳定的 `code` 和 `fields`，保留原有 ValueError
继承及中文提示。缺少映射使用 `missing_account_mapping`，其他行校验继续
使用 `invalid_record`。预览只读取结构化元数据，不再解析中文异常文本。
原有预览返回的行号、重复主键和已知字段语义保持不变。

Pydantic 未知列名可能包含敏感内容，因此准备层异常文本和字段元数据均只保留
模型已知字段；预览输出端仍再次按模型白名单过滤。日期/金额解析失败继续提供
date/cost 两个候选字段，不改变业务校验或自动修正输入。

数据库配置异常先于通用 ValueError 捕获，显示本机目标与连接配置提示，不再
误报为文件格式问题，也不输出原始配置异常。导入 status 未提供 --plan-id 时
在读取数据库配置之前明确提示缺少计划编号，不要求无关的输入文件或映射。

## 验证与边界

新增回归覆盖提示文案变化仍保持分类、未知敏感列名过滤、结构化错误码和字段、
配置故障脱敏提示，以及缺少计划编号不读取配置。相关纯测试 32 项通过，完整
隔离 MySQL 测试 94 项通过；Ruff、格式检查及 mypy strict 均通过。

本步不涉及迁移、运行库数据或页面样式，不改变金额、主键及账户映射业务规则。
数据库诊断持久化、性能评估和其他入口的错误统一仍独立推进。
