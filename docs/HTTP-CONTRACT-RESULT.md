# 规范收敛第四步：公开 HTTP 响应模型

2026-11-10。本步只固定既有成功响应契约，不增加业务字段、数据来源或写入接口。

## 模型与路由

新增 http_models.py：LoginResponse、VisibleAccount、CurrentUserResponse、KeywordMetrics、KeywordReportRow、ReportFilters 和 KeywordReportResponse。类与文件头包含中文职责说明。

登录成功、/auth/me 与 /reports/keywords 显式声明 response_model 并返回有类型的模型。服务层 SQL 与指标函数保持原有边界，没有强制查询服务依赖 HTTP 模型。退出继续返回无正文 204；错误响应仍由现有 HTTPException/参数错误入口处理，不宣称已统一所有错误模型。

模型 strict 拒绝隐式类型转换，extra=forbid 拒绝服务端误加字段，不通过丢弃额外键掩盖契约漂移。错误文字隐藏原始输入值；这不替代调用方对 .errors() 和日志内容的治理。

## 保持的字段语义

- 金额使用十进制字符串；消耗/CPC/比率四位，线索成本两位，避免 JSON 浮点精度变化。约束不新增舍入，只验证原服务已产生的格式。
- 零分母相关指标仍显式 null，筛选账户未指定仍为 null。报表采用 exclude_unset 而非 exclude_none，不能误删前端依赖的 null。
- 正式来源的 conv_78/92 必须为整数，仍不加入综合线索；合成来源不允许提供这两个不存在的字段。模型默认值不应伪造零或 null 输出。
- data_source 与 applied_filters.source 一致；当前页记录不能超过 page_size 或 total。列表/汇总各有明确结构，不将列表行的 keyword 混进 summary。
- 身份/账户 ID 保持整数，列表名称保持字符串；账号和会话模型不包含密码、令牌或数据库配置。

OpenAPI 为上述路由引用具体模型，能显示 rows、summary、筛选值、金额字符串、可空值及来源枚举。未知转化的“正式必有/合成省略”额外约束由模型校验器执行，并以字段说明记录；OpenAPI 的单一响应模型没有完全表达这一条件分支，客户端仍需遵循 data_source。

## 验证

全套 66 passed，涵盖现有数据库、认证与报表回归，以及新增金额类型/小数位、null 保留、来源一致性、未知转化条件、额外秘密字段拒绝及 OpenAPI 模型引用测试。HTTP 集成实际检查正式/合成序列化差异，不只验证模型本身。

新模型在 HTTP 路由边界校验，服务端输出错误不会被当作成功结果返回；报表模型构造在原输入 ValueError 捕获之外，避免将内部响应缺陷误报成用户请求 422。

本轮无数据库迁移、账号或正式数据修改，页面不变。当前 8082 非之前 PID 记录中的启动方式，本轮不终止该进程；模型和 OpenAPI 已在独立测试应用验证，当前运行预览需正常重启后加载。TestClient 弃用提示仍在。
