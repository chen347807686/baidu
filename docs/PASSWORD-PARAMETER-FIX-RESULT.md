# 密码参数兼容与失败计算路径修复

2026-11-10。修复 ITERATIONS 与占位哈希耦合、修改策略导致旧哈希失效的问题。不修改运行库密码或会话，不增加数据库迁移。

## 参数和格式

- 继续使用 pbkdf2_sha256$轮数$盐$摘要，不更换算法或重置用户密码。新建密码默认 600000 次，允许的新策略范围为 600000–2000000；越界策略显式报错，不能静默破坏失败路径。
- 按每条记录存储的轮数验证，支持历史范围 100000–2000000；100000 只是读取历史兼容下限，不是新密码安全基线。当前项目已创建的 600000 记录完整兼容。超范围、其它算法、损坏盐或摘要一律拒绝，不执行来自记录的无界计算。
- 移除 DUMMY_HASH 及其硬编码轮数。未知用户向验证入口传 None，与损坏记录使用统一占位计算路径。

## 计算预算与限制

每次验证的 PBKDF2 总迭代预算固定为 2000000：先按记录参数计算校验摘要，再独立补足剩余计算。缺失/损坏记录用当前参数计算后补足，超长或无法 UTF-8 编码的密码也计算后拒绝。比较使用 compare_digest，补算不会修改原摘要。

这避免了未知用户在参数校验时直接零计算返回，但不构成端到端恒定时间保证：解析、数据库查询/行锁、网络、单次或两次函数调用等仍可能有耗时差异。没有通过睡眠伪造耗时，也没有声称消除所有统计时间信号。

代价是验证成本上升：原默认只计算 600000 次，现在失败/正常校验总预算为 2000000；成功升级时还需生成新哈希。完整测试耗时也相应增加。上线前须结合目标硬件、限速、并发和延迟目标评估；本次未做生产压测，不能将此预算直接视为生产最优策略。

## 成功登录升级

较弱且受支持的历史记录在正确密码、启用账号成功登录后更新为当前参数；新随机盐，明文密码不变。更强记录不降级，错误密码、未知用户、停用用户不更新凭据。

登录沿用凭据行锁，哈希升级与新会话在调用方同一事务里；回滚恢复原哈希并撤销本次新会话，原有有效会话保留。此类参数升级不是密码重置，不触发“全部设备退出”。改密工具仍保持原有全会话撤销行为。
